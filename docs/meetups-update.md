# Встречи: завершение, участие, напоминания, приглашения и избранное

Версия сервера: `meetups-v4`. API_VERSION остаётся 4; новый клиент дополнительно проверяет функцию meetupLifecycle.

## Что добавлено

### Итог и завершение встречи

После начала у организатора появляются две кнопки: «Завершить: состоялась» и «Не состоялась». До начала можно отменить встречу. Завершить чужую встречу нельзя. Повторное завершение с тем же итогом не отправляет повторное уведомление; изменить уже зафиксированный итог через эту кнопку нельзя.

Завершённая встреча сразу уходит из общей ленты: состоявшаяся — в «Мои → Прошедшие», несостоявшаяся — в «Отменены / не состоялись». Отметку ставит организатор, это не независимая проверка посещения. Если организатор ничего не отметил, встреча уходит в архив после полуночи по Москве с подписью «Итог не указан». Организатор может указать итог из архива.

Отзывы доступны сразу после «Состоялась» подтверждённым участникам общей встречи, которые действительно встретились и подтвердили это в форме. Для «Не состоялась» и отменённых встреч отзывы недоступны. Для старых архивных встреч без итога сначала нужна отметка организатора. Существующие опубликованные отзывы не удаляются.

### Отмена участия

До начала встречи участник может «Отменить участие» или «Отозвать заявку». За час до начала и ближе показывается дополнительное предупреждение. После выхода одобренного участника освобождается место, организатор получает уведомление, точный адрес/приватная ссылка и контакты по этой встрече закрываются. Дружба или другая одобренная встреча могут сохранять отдельное основание доступа к контакту.

Повторный выход не уменьшает число мест ещё раз. Организатор не может снова одобрить отозванную заявку без новой подачи участником. Участник может подать её повторно до начала, если остались места. После начала отмена участия этой кнопкой недоступна, чтобы не менять историю состоявшейся встречи.

### Приглашение

В подробностях есть «Поделиться». Ссылка открывает Telegram-бота с кнопкой перехода именно к выбранной встрече. Если системное меню отправки недоступно, ссылка остаётся в поле для копирования. В ссылке нет точного адреса, приватной комнаты или контактов. Получатель всё равно проходит обычный вход и подаёт заявку.

Ссылка сейчас ведёт через Telegram-бота; отдельной ссылки приглашения через MAX этот выпуск не создаёт. Контакт MAX можно привязать через Telegram, как в предыдущем обновлении.

### Избранное

Закладка на карточке и кнопка в подробностях сохраняют встречу. Посмотреть сохранённое: «Мои → Избранное». Это не заявка на участие. Избранное хранится в базе отдельно для каждого пользователя. Завершённые и отменённые встречи остаются в избранном, пока их не удалить. Скрытые модерацией публикации не выдаются в списке.

### Фильтры

Дата (сегодня, завтра, 7 дней), занятие, район/метро/место, спорт/игры, встречи друзей, формат онлайн/офлайн, свободные места, только избранное. Есть «Сбросить фильтры». Даты фильтруются по Москве. «Есть свободные места» показывает встречи, в которые ещё можно подать заявку: они не начались и не заполнены.

## Напоминания

Сервер проверяет напоминания раз в минуту, пока процесс работает. Они идут организатору и одобренным участникам, у которых включены уведомления, примерно за сутки и за час. Текст содержит дату и время по Москве, публичное место и подсказку открыть подробности в «Моих». Вышедшие, ожидающие одобрения и заблокированные пользователи не получают эти напоминания; завершённые, отменённые и скрытые встречи пропускаются.

Уже отправленные напоминания записываются в PostgreSQL и не пересылаются при обычном перезапуске. После ошибки доставки выполняется до трёх попыток с паузой не меньше пяти минут. При обрыве связи сразу после фактической доставки, до сохранения подтверждения, редкий повтор всё же возможен — Telegram не даёт транзакции, общей с нашей базой.

После короткого простоя суточное напоминание допускается в интервале от 24 до 23 часов до начала; часовое — в течение последнего часа, пока встреча ещё не началась. Если сервер был выключен всё это время, пропущенное уведомление после начала не отправляется.

Free Render засыпает без входящих запросов. Поэтому встроенный таймер сам по себе не гарантирует отправку, когда никто не открывает приложение. Подготовлен внешний запуск GitHub Actions; он не включится фактически, пока не заполнены секреты. Подключение описано в отдельном файле `shodka-reminders-setup.md`.

## Выкладка по шагам

1. Скачайте `shodka-meetups-update.zip` и распакуйте.
2. Откройте GitHub → `shmelyovsk/shodka-mvp-v2` → Code, ветка main.
3. Add file → Upload files.
4. Перетащите всё содержимое распакованной папки `shodka`, включая `.github`, `apps`, `tests`, `docs`, `.env.example`, `compose.yaml`, `package.json`. Саму внешнюю папку shodka не загружайте.
5. Файл с личным секретом планировщика находится отдельно от архива. В GitHub его загружать не нужно.
6. Название изменения: «Завершение встреч, избранное и напоминания».
7. Создайте новую ветку `meetup-features`, сохраните файлы.
8. Create pull request → Merge pull request → Confirm merge.
9. Render → `shodka-mvp-v2` (без -1) → Manual Deploy → Deploy latest commit, если сборка ещё не запустилась автоматически.
10. Дождитесь Live.
11. Откройте https://shodka-mvp-v2.onrender.com/health. Нужны `release: "meetups-v4"`, `apiVersion: 4`, `storage: "postgres"`.
12. Затем Render → `shodka-mvp-v2-1` → Deploy latest commit, дождитесь Live.
13. Полностью переоткройте мини-приложение.
14. Для внешних напоминаний выполните отдельную инструкцию.

Токены ботов, DATABASE_URL и MODERATOR_USER_IDS менять не нужно. Новых npm-пакетов и миграции таблиц нет. Все новые данные сохраняются в существующей базе. Архив включает ранее подготовленные поддержку, модерацию, подтверждённые контакты и разные значки навигации.

## Проверка после обновления

1. Сохраните встречу закладкой → «Мои → Избранное» → убедитесь, что она там есть. Переоткройте приложение, проверьте сохранение.
2. С другого аккаунта подайте заявку и одобрите её организатором.
3. Отмените участие: число занятых мест должно уменьшиться, организатор получит сообщение.
4. Подайте заявку снова, примите её. Вышедшего участника нельзя вернуть одним повторным одобрением старой заявки до её новой подачи.
5. «Поделиться» → скопируйте ссылку другу → в боте нажмите кнопку. Должна открыться именно эта встреча.
6. Проверьте формат онлайн/офлайн, свободные места, избранное и сброс фильтров.
7. Создайте тестовую встречу на ближайшее время. После наступления времени организатор сможет отметить «Состоялась». Она окажется в прошедших, участникам станут доступны отзывы.
8. Для другой начавшейся встречи выберите «Не состоялась»: она попадёт в соответствующий архив, отзывы о ней недоступны.
9. Проверьте напоминания отдельно: создайте встречу с началом менее чем через час, включите уведомления, присоединитесь и одобрите второго участника. При работающем сервере сканер отправит часовое напоминание в ближайшую минуту; повторно уже отправленное не должно приходить.

Локально проверены: компиляция TypeScript сервера и клиента, сборка Vite; доступы и повторные запросы; завершение/архив/отзывы; выход и повторная подача; приватность избранного и ссылок; доставка напоминаний с имитацией Telegram/MAX, повторные сканирования, лимиты попыток; сохранение новых данных после закрытия и повторного открытия PostgreSQL. Реальную доставку, системное меню «Поделиться» и вид на телефоне нужно проверить после выкладки.
