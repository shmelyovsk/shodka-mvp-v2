# Обновление community-v4

## Список заявок

В «Заявках ко мне» остаются только ожидающие решения заявки на будущие встречи. Принятые, отклонённые, отозванные заявки и заявки на уже начавшиеся, завершённые, отменённые или скрытые встречи убраны из основного списка и счётчика. При открытом разделе список обновляется раз в минуту; после решения — сразу.

История и статусы в базе сохраняются, состав участников, контакты и отзывы не удаляются. Принятых участников можно посмотреть в самой сходке. Для технического доступа владельца история доступна через прежний endpoint с `?history=true`; отдельного экрана архива заявок этот выпуск не добавляет.

## Формулировки

Поле «Уровень» заменено на «Кого ждём».
В форме: «Любой уровень», «Новичков», «С опытом».
В карточке и подробностях: «Кого ждём: участников любого уровня / новичков / участников с опытом».
Значения существующих встреч сохранены, перезаполнять их не нужно.

## Расширенный фильтр

Словарь вынесен в `apps/server/src/textDictionary.ts`, алгоритм — в `apps/server/src/textFilter.ts`. Добавлены русские и английские ругательства, оскорбительные формы, некоторые уничижительные обозначения и прямые угрозы.

Проверка учитывает регистр, ё/е, невидимые символы, часть транслита и неправильной раскладки, смешение похожих букв, распространённые цифровые замены, повторение букв, точки/дефисы/подчёркивания, отдельные буквы с пробелами, некоторые маски со звёздочками.

Это словарная проверка с шаблонами, а не понимание смысла. Она не гарантирует распознавания любого обхода, не различает все цитаты/шутки/контексты и иногда может ошибиться. Неоднозначные случаи остаются предметом ручного разбора по жалобам. Изображения не проверяются. Поддержка и причины жалоб не пропускаются через этот фильтр, чтобы пользователь мог процитировать проблему.

Проверяются публичные поля профиля, сходки и текст отзыва. Правила одинаковы для обычных пользователей и модераторов. При совпадении новое сохранение отклоняется с просьбой переформулировать текст. Исключения для модераторов нет.

После обновления сервер также проверит ранее опубликованные активные сходки, профили и видимые отзывы. Найденные совпадения попадут в очередь жалоб с пометкой автоматической проверки. Новая версия словаря сама не удаляет публикации и не блокирует аккаунты. Одинаковая автоматическая жалоба не дублируется после перезапуска; уже рассмотренная не открывается повторно этим сканером.

В панели модерации появилось объяснение защиты аккаунтов команды. Для сходки или отзыва модератора кнопка «Скрыть публикацию» доступна. Для жалобы непосредственно на его профиль предупреждение и блокировка остаются недоступны — панель объясняет, как пожаловаться на саму публикацию.

Полный словарь для просмотра вынесен отдельно в `shodka-expanded-filter-list.txt` (папка outputs). Корни проверяются на границе слова, а не в любом месте строки: например, «учёба», «хлеб», «команда», «мандарин», «педикюр», «Херсон» и названия игр из каталога проходят проверку.

## Выкладка

1. Скачайте `shodka-community-update.zip` и распакуйте.
2. GitHub → shmelyovsk/shodka-mvp-v2 → Code, ветка main → Add file → Upload files.
3. Загрузите всё содержимое распакованной папки `shodka`: apps, tests, docs, package.json. Саму внешнюю папку shodka не загружайте.
4. Название коммита: «Фильтр текста, заявки и формулировки».
5. Создайте ветку community-update, сохраните файлы.
6. Create pull request → Merge pull request → Confirm merge.
7. Render → shodka-mvp-v2 (без -1) → Manual Deploy → Deploy latest commit, если обновление ещё не запустилось автоматически.
8. Дождитесь Live.
9. Откройте https://shodka-mvp-v2.onrender.com/health. Должны быть release: "community-v4", apiVersion: 4, storage: "postgres".
10. Затем обновите shodka-mvp-v2-1 и дождитесь Live.
11. Полностью переоткройте мини-приложение.

Токены, секрет планировщика, DATABASE_URL и MODERATOR_USER_IDS менять не нужно. Новых пакетов и миграции таблиц нет. Workflow напоминаний в этом архиве не обновляется.

## Проверка после выкладки

1. В «Заявках ко мне» должны остаться только будущие ожидающие заявки. После принятия карточка исчезает, участник остаётся в сходке.
2. Отклонённая или отозванная заявка не возвращается в основной список. Начавшаяся встреча тоже не должна оставлять там старые заявки.
3. Проверьте форму создания, карточку и подробности: везде «Кого ждём» с понятными вариантами.
4. Попытка сохранить явное ругательство в названии должна отклоняться у обычного пользователя и модератора. Проверяйте на тестовой записи, не публикуя оскорбления.
5. Обычные названия «Бадминтон», «Counter-Strike 2» и описание «Играем после учёбы» должны сохраняться.
6. Откройте «Модерация и жалобы». Если в старых публикациях найдены совпадения, разберите новые автоматические жалобы с учётом контекста.
7. На жалобе на сходку модератора должна быть кнопка скрытия и пояснение защиты аккаунта.

Через API проверены одинаковые правила для модераторов и обычных пользователей, фильтр профиля/сходок/отзывов, очистка списка заявок без удаления истории. Проверен сканер старых текстов без дублей и автоматического удаления. Telegram/MAX в проверках заменены имитацией; вид на телефоне нужно проверить после выкладки.
