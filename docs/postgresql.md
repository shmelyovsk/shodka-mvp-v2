# Подключение PostgreSQL

## Как работает эта версия

- При непустом DATABASE_URL сервер хранит пользователей, сходки и заявки в PostgreSQL. При пустом — работает прежнее JSON-хранилище.
- В PostgreSQL автоматически создаётся таблица shodka_state со схемой версии 1. Данные MVP пока хранятся одним документом JSONB; отдельные реляционные таблицы пользователей/сходок — следующий этап при росте нагрузки.
- Изменения записываются атомарно с проверкой версии. Устаревшая запись не заменяет новые данные: API вернёт 409 и предложит повторить действие.
- Новая база создаётся пустой, без демонстрационных пользователей и сходок. После входа человек указывает возраст заново, если его профиль не был импортирован.
- Перезапуск API не удаляет данные PostgreSQL. Доступность самой базы и резервные копии зависят от провайдера.
- Если DATABASE_URL настроен, но база недоступна, сервер не переключается на JSON. Сбой подключения останавливает запуск; /health возвращает 503 при потере связи во время работы. Исправный /health показывает storage: postgres.
- Настройки TLS берутся из URL провайдера. Код не отключает проверку сертификатов.

## До обновления Render: существующие данные

Переключение хранилища не копирует JSON с действующего сервера автоматически. Резервную копию data/db.json нужно получить ДО развёртывания/перезапуска: на бесплатном Render локальный файл может исчезнуть. Экспорт из браузера пока не реализован, Shell на бесплатном тарифе Render недоступен. Если в текущем приложении есть важные сходки/заявки, сначала согласуйте способ их сохранения; не рассчитывайте, что новый релиз перенесёт их сам.

Если данных пока нет или есть только тестовые, можно начать с пустой базы. Существующий пользователь Telegram/MAX получит тот же идентификатор платформы, но должен будет снова указать возраст. Созданные в JSON сходки автоматически в новой базе не появятся.

Никакие файлы резервных копий с персональными данными не загружайте в GitHub.

## Бесплатное подключение

Для проекта без бюджета можно использовать PostgreSQL на Neon Free и оставить API/frontend на Render. Ограничения бесплатного плана проверяйте перед созданием проекта: https://neon.com/docs/introduction/plans

Бесплатная PostgreSQL в самом Render истекает через 30 дней: https://render.com/docs/free — она не подходит как постоянное бесплатное хранилище этого проекта.

1. Зарегистрируйтесь на https://console.neon.tech/ и создайте проект shodka на Free.
2. Выберите регион, близкий к вашему API Render, и сохраните проект.
3. В Connect скопируйте PostgreSQL connection string. Сохраните параметры TLS из выданной строки. Это секрет с паролем, не присылайте его в чат.
4. Загрузите обновлённый код в GitHub. DATABASE_URL пока не задавайте, если нужно сначала сохранить старые данные.
5. В Render откройте сервис API shodka-mvp-v2 → Environment и добавьте DATABASE_URL с полученной строкой.
6. Команда сборки остаётся: npm ci --include=dev && npm run build --workspace @shodka/server
7. Save, rebuild, and deploy. Frontend и токены ботов менять не нужно.
8. Откройте API /health: ожидается status: ok и storage: postgres.
9. В Telegram создайте тестовую сходку. Перезапустите сервис через Render, снова откройте приложение и убедитесь, что сходка и возраст профиля сохранились.

На бесплатном Render API всё ещё может засыпать; PostgreSQL решает потерю данных, но не задержки ответа ботов во время сна сервера.

## Импорт имеющейся резервной копии JSON

Исполнять только с доверенной резервной копией, с сервера/компьютера, где доступен URL базы. Сначала остановите поступление новых данных в целевую базу. Команда откажется работать, если в PostgreSQL уже был изменён начальный пустой документ. Импорт не перезаписывает работающую базу.

1. Задайте DATABASE_URL в локальном .env, не коммитьте его.
2. Выполните npm ci --include=dev и npm run build --workspace @shodka/server.
3. Выполните:

```text
npm run db:import --workspace @shodka/server -- C:/полный/путь/backup.json
```

В backup.json обязательны массивы users, activities, applications, уникальные строковые id, корректный возраст и существующие ссылки на пользователей/сходки. Данные импортируются одним UPDATE, частичного импорта нет.

## Проверки разработчика

```text
npm run typecheck
npm test
npm run test:postgres
```

SQL проверяется в PGlite — настоящем PostgreSQL в WASM. Проверяются создание базы, запись, повторная инициализация, конфликт версий, отказ перезаписи при импорте и сохранение данных после закрытия/повторного открытия движка с диска. Сценарий API MAX ↔ Telegram проверяется с JSON fallback, сетевые API ботов заменены заглушками.

Подключение node-postgres по сети, TLS, конкретный облачный URL и реальные уведомления нужно проверить после создания вашей базы. Эти проверки не имитируют доступность или условия облачного провайдера.
