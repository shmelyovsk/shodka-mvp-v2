# Помощь и предложения — обновление support-v4

## Что добавлено

В Telegram-боте:
- `/help` — меню «Как пользоваться», «Сообщить о проблеме», «Предложить улучшение».
- `/idea` — отправка предложения.
- `/cancel` — отмена ввода обращения.
- `/support` остаётся командой добровольной поддержки проекта.

После выбора отправьте одно сообщение с описанием. Можно приложить один скриншот с подписью, в том числе как файл изображения до 10 МБ. Фото без описания бот попросит отправить снова с подписью. Пароли, коды входа и платёжные данные отправлять не нужно. До пяти обращений за час от одного пользователя. Черновик режима ввода сохраняется в базе, отменить его можно `/cancel` или `/start`.

В мини-приложении: профиль → «Обращения: проблемы и идеи». Кнопка видна аккаунтам из уже настроенного MODERATOR_USER_IDS. Вкладки «Проблемы» / «Идеи», фильтры открытых и решённых. Статусы: новое, в работе, решено. После отправки ответа статус меняется отдельно. Можно вернуть решённое обращение в работу.

Ответ отправляется ботом в личный чат пользователя, личные контакты модератора не раскрываются. История показывает отправленные и недоставленные ответы. Если доставка не подтверждена, проверьте историю перед повторной отправкой. Telegram может отказать в доставке, если пользователь заблокировал бота.

Скриншот можно получить кнопкой «Получить скриншот в Telegram». Для этого модератор должен открыть мини-приложение через Telegram и ранее написать `/start` боту. Вложения хранятся как закрытые Telegram file_id; публичные ссылки не создаются. Встроенного просмотра вложений в панели пока нет. Автоматических уведомлений команде о новых обращениях пока нет — проверяйте панель самостоятельно.

Этот выпуск добавляет приём обращений именно в Telegram. Подключение аналогичного сценария в MAX — отдельный этап после настройки нового MAX-бота.

## Выкладка

1. Распакуйте shodka-help-and-ideas.zip.
2. Откройте GitHub → shmelyovsk/shodka-mvp-v2 → Code, ветка main.
3. Add file → Upload files.
4. Перетащите всё содержимое папки shodka: apps, tests, docs и package.json. Саму внешнюю папку shodka не загружайте.
5. Сообщение коммита: «Помощь пользователям и предложения».
6. Выберите создание новой ветки, назовите help-and-ideas.
7. Сохраните, создайте Pull Request в main, затем Merge pull request → Confirm merge.
8. Render → shodka-mvp-v2 (сервер без -1) → Manual Deploy → Deploy latest commit, если обновление ещё не запустилось автоматически.
9. Дождитесь Live.
10. Откройте https://shodka-mvp-v2.onrender.com/health. Должны быть apiVersion: 4, release: "support-v4", storage: "postgres".
11. Render → shodka-mvp-v2-1 → Manual Deploy → Deploy latest commit. Дождитесь Live.
12. Полностью закройте мини-приложение и откройте заново.
13. Напишите боту /help. Если меню команд визуально старое, команду можно написать вручную; закройте и снова откройте чат для обновления меню.

Токены и DATABASE_URL менять не нужно. Новых зависимостей и миграции таблиц нет. MODERATOR_USER_IDS остаётся прежним. Общая база сохраняет встречи и профили, к ней добавляются обращения и черновики.

## Проверка после выкладки

1. /help → «Как пользоваться»: должна появиться инструкция.
2. /help → «Сообщить о проблеме»: отправьте тестовое описание со скриншотом в одном сообщении. Бот подтвердит получение и выдаст номер.
3. /idea: отправьте тестовую идею. Проверьте подтверждение.
4. /idea → /cancel: бот должен отменить отправку.
5. Откройте профиль модератора → «Обращения: проблемы и идеи».
6. Найдите проблему, получите скриншот в Telegram, поставьте «В работе».
7. Введите ответ и подтвердите отправку. Ответ должен прийти от бота отправителю обращения.
8. Поставьте «Решено» — обращение появится в решённых.
9. Проверьте идею во вкладке «Идеи».
10. Перезапустите сервер и убедитесь, что обращения и история ответов остались.

Локально выполнены компиляция TypeScript сервера и клиента, сборка Vite, проверки сценария поддержки, прав, статусов, ошибок доставки, команды бота и прежние интеграционные сценарии. Telegram заменён имитацией — реальные сообщения во время тестов не отправлялись. Вид на телефоне и реальную доставку нужно проверить после выкладки.
