# Включение напоминаний при спящем Render

Код уже подготовлен в `.github/workflows/reminders.yml`. Нужно связать GitHub и API одним случайным секретом. Дополнительный платный worker для этого варианта не создаём.

## 1. Секрет

Откройте отдельный локальный файл `shodka-reminder-secret.txt` из папки outputs. В нём одна строка со случайным значением. Копируйте только эту строку, без пробелов. Файл не входит в архив обновления: не загружайте его в репозиторий и не публикуйте в переписке.

## 2. Render

1. Откройте Render → `shodka-mvp-v2` (сервер без -1).
2. Environment → Add Environment Variable.
3. Key: `REMINDER_CRON_SECRET`.
4. Value: строка из локального файла.
5. Сохраните изменения с перезапуском/деплоем сервиса.
6. Дождитесь Live. В `/health` должна остаться версия `meetups-v4` и storage `postgres`.

Встроенный таймер включён по умолчанию. `REMINDERS_ENABLED=false` отключает именно таймер процесса; защищённый внешний запуск при настроенном секрете продолжает работать.

## 3. GitHub

1. Откройте репозиторий `shmelyovsk/shodka-mvp-v2`.
2. Settings → Secrets and variables → Actions.
3. На вкладке Secrets нажмите New repository secret.
4. Name: `REMINDER_CRON_SECRET`.
5. Secret: та же строка, что добавили в Render. Нажмите Add secret.
6. Снова New repository secret.
7. Name: `REMINDER_URL`.
8. Secret: `https://shodka-mvp-v2.onrender.com/internal/reminders`.
9. Нажмите Add secret.

Если раздел настроек недоступен вашему GitHub-аккаунту, эти два секрета добавляет владелец репозитория.

## 4. Первый запуск

1. Перейдите во вкладку Actions репозитория.
2. Слева выберите `Meetup reminders`.
3. Нажмите Run workflow, выберите main, подтвердите запуск.
4. Дождитесь зелёного результата.
5. Откройте шаг Trigger reminder scan. Ответ `{"ok":true,"sent":0}` означает, что запуск работает, но новых получателей сейчас нет.
6. Если 401 — значения REMINDER_CRON_SECRET в Render и GitHub отличаются. Если 404 — сервер ещё старый или секрет на сервере отсутствует/слишком короткий. 503 — повторите позже и проверьте сервер.
7. Создайте тестовую встречу менее чем через час с включёнными уведомлениями. У организатора и одобренных участников должно появиться часовое напоминание. Его мог уже отправить встроенный таймер — тогда внешний запуск покажет sent:0 и не продублирует сообщение.

Затем workflow запрашивает сканирование примерно раз в пять минут. Переход по адресу через браузер не проверяет защищённый POST-запуск: обычный GET не должен запускать рассылку.

## Ограничения

Это не гарантия доставки строго в минуту: GitHub может задерживать задания, пользователь может заблокировать бота или отключить уведомления, Render может быть недоступен. В публичном репозитории расписание может отключиться после длительного отсутствия активности. Проверяйте вкладку Actions, если напоминания перестали приходить. [Правила расписания GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

Частые входящие запросы могут держать API активным круглосуточно. Это расходует бесплатные часы Render; лимит общий для Free web services рабочего пространства. Если там несколько таких сервисов, следите за суммарным использованием. При исчерпании лимита Render может приостановить Free-сервисы до следующего месяца. [Ограничения Render Free](https://render.com/docs/free).

Для отключения внешнего запуска откройте Actions → Meetup reminders → меню справа → Disable workflow. Либо удалите соответствующие секреты из GitHub. При смене секрета обновите его и в GitHub, и в Render.
