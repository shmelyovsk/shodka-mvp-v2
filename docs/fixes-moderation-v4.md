# Исправления и модерация — API v4

## Что исправлено

- Профили, друзья, сохранение ника/контакта и онлайн-встречи теперь защищены проверкой совместимости сайта и API. Перед обращением к данным клиент проверяет /api/capabilities и ожидает apiVersion=4. На старой версии сервера показывается понятное сообщение вместо HTML/JSON-ошибки и ложного «сохранено».
- API возвращает JSON и для неизвестных маршрутов, а клиент отдельно обрабатывает HTML, некорректный JSON и сетевые сбои. Ошибка не содержит HTML страницы хостинга.
- После сохранения профиля дополнительно проверяются возвращённые ник и Telegram-контакт. Поля управляемые, значения после сохранения/открытия остаются. Намеренно очищенный контакт больше не подставляется обратно из Telegram при следующем входе.
- Уровень подготовки удалён из своего и публичного профиля. Уровень конкретной встречи остаётся. Старое поле в базе не удаляется, чтобы не ломать совместимость.
- Для компьютерных игр инвентарь убран из формы и деталей. Даже если старый клиент отправит его, сервер для категории games сохраняет пустое значение.
- Для игр личный формат называется «Компьютерный клуб», второй вариант — «Онлайн, из дома». Район и место нужны только для очного формата. Ошибки обязательных полей выводятся по-русски.
- Нижние вкладки: Сходки, Создать, Друзья, Мои. Запросы и поиск друзей — в Друзьях. Заявки организатору — в Моих, отдельная кнопка с количеством ожидающих.

## Что установлено диагностикой

Публичный frontend загружает новые экраны и использует правильный адрес API. Публичный API отвечает, PostgreSQL подключена. По старому /health нельзя было точно определить версию работающего сервера; без личных данных запуска проверка защищённых маршрутов не подтверждает, что они установлены. Поэтому несовпадение развёрнутых версий было вероятной причиной, а не доказанным фактом.

В этой версии /health и /api/capabilities показывают apiVersion:4, release:social-moderation-v4. /health также показывает storage:postgres и короткий commit, если Render передал RENDER_GIT_COMMIT. По этим полям можно точно проверить развёртывание.

## Как загрузить обновление

1. Распаковать архив. Внутри папки shodka находятся изменённые файлы. Загрузить её содержимое через GitHub Upload files в корень shmelyovsk/shodka-mvp-v2.
2. Создать ветку fixes-moderation-v4, pull request и объединить после проверки.
3. В Render открыть API shodka-mvp-v2 → Manual Deploy → Deploy latest commit. Команда сборки остаётся npm ci --include=dev && npm run build --workspace @shodka/server.
4. Дождаться Live. Открыть https://shodka-mvp-v2.onrender.com/health и проверить apiVersion:4, release:social-moderation-v4, storage:postgres.
5. Если версии 4 нет, не переходить к frontend: проверить, что API Render подключён к нужному репозиторию и ветке main, и открыть логи последнего развёртывания.
6. После проверки API обновить frontend shodka-mvp-v2-1 через Deploy latest commit, дождаться Live.
7. Полностью закрыть и снова открыть мини-приложение. Проверить ник/контакт после сохранения и повторного входа, открытие профилей/друзей и создание онлайн-игры без адреса.

DATABASE_URL, Neon, токены и VITE_API_URL менять не нужно. Эта версия не удаляет существующие профили, встречи, друзей и отзывы. Новые поля и массивы JSONB необязательные.

## Модерация: доступ для двух аккаунтов

По умолчанию доступ команды выключен. Он задаётся доверенными идентификаторами платформ, а не именами и никами.

1. После обновления сервера каждый из вас отправляет /id своему Telegram-боту. Ответ имеет вид «Ваш ID СХОДКИ: telegram:123456».
2. В Render API → Environment добавить MODERATOR_USER_IDS. Значение — два ID через запятую, например telegram:123456,telegram:654321. Это пример, нужны ваши реальные ID. Поддерживаются также max:число, если известен ID профиля MAX; команда /id в этой версии добавлена в Telegram.
3. Сохранить переменные с новым запуском API. Закрыть и открыть мини-приложение.
4. В личном кабинете двух указанных пользователей появится «Модерация и жалобы». У остальных кнопки нет, а сервер отклоняет попытки обращения к панели и решениям.

Не указывайте здесь username Telegram, ник СХОДКИ или токен бота. Ник «admin» никаких прав не даёт. Снять доступ модератора можно только изменением MODERATOR_USER_IDS в настройках сервера. Через панель нельзя заблокировать ни себя, ни второго аккаунта команды.

## Автоматическая проверка текста

Сервер проверяет новые названия, описания, занятия, места, пользовательские поля профиля и тексты отзывов на явные грубые выражения/угрозы. Есть базовая нормализация ё/е, незаметных символов и части подмен букв/разделителей. Явная грубость в новом автоматически полученном имени мессенджера заменяется нейтральным «Участник».

Это ограниченный фильтр, а не полноценное понимание смысла. Он не распознает все способы обхода и может ошибаться. Жалобы и ручной разбор нужны для контекста, косвенных оскорблений и спорных случаев. Ранее опубликованные данные не сканируются задним числом. Фотографии автоматически не классифицируются.

## Жалобы и панель

Пользователь может пожаловаться на сходку, профиль или отзыв и указать причину. Одна жалоба на один объект от одного пользователя; повторы блокируются.

Панель содержит новые жалобы и историю решений, автора, причину и текст публикации. Доступны:
- скрыть/восстановить сходку либо отзыв;
- предупредить пользователя/снять предупреждение;
- ограничить аккаунт/восстановить доступ;
- отклонить жалобу.

Все решения записываются в moderationLog с ID модератора и временем. Скрытые сходки исчезают из публичной ленты, но остаются в истории организатора и принятых участников с пометкой. Скрытый отзыв не участвует в средней оценке; восстановление возвращает его в рейтинг. Скрытие не даёт автору права повторно оценить ту же встречу.

Блокировка закрывает публичный профиль, его сходки в ленте, доступ к чужим приватным разделам и действия публикации/заявок. Свой профиль доступен для просмотра уведомления и исправления текста. Снятие блокировки не удаляет историю решений. Сами записи не удаляются. Жалоба не блокирует аккаунт автоматически — решение принимает команда.

Старые reviewReports включаются в новую очередь. Отдельных уведомлений ботом о новых жалобах пока нет — очередь нужно открывать в кабинете.

## Проверки

Прошли TypeScript frontend/backend, Vite production build, интеграционные проверки API, тесты клиентских сообщений при HTML/старой версии API, тесты команд /id и /support с заглушкой Telegram, проверки архива и PostgreSQL.

Проверены права модератора и отказ посторонним, защита аккаунтов команды, скрытие/восстановление публикаций, перерасчёт рейтинга, предупреждение/его снятие, блокировка/снятие, журнал действий, текстовый фильтр, сохранение ника/контакта после повторного входа, сохранение намеренно очищенного контакта, создание онлайн-встреч без физического адреса.

Автоматические тесты не затрагивают рабочую Neon и не отправляют реальные сообщения. Экранные сценарии на телефоне и доступ команды нужно проверить после развёртывания и настройки ID.
