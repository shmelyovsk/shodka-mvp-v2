# Сходка

Веб-приложение и чат-бот для MAX, которые помогают людям 16+ находить компанию для занятий спортом. После регистрации веб-интерфейса в MAX его можно использовать как Mini App.
 
## Основной сценарий
 
1. Пользователь открывает чат-бот.
2. Выбирает подходящую сходку в соответствии с нужными параметрами и отправляет заявку.
3. Организатор подтверждает или отклоняет заявку.
4. После подтверждения активность появляется в разделе «Мои сходки».
5. Пользователь видит статус заявки и напоминание о предстоящей встрече внутри приложения. Персональные уведомления через бот MAX можно подключить после связывания профиля приложения с MAX ID пользователя.
 
## Статус MVP
 
Работают каталог, фильтры по дате, виду спорта и месту, создание активности, заявки, подтверждение организатором, раздел «Мои сходки» и отмена активности. Цена явно указана за одного человека. В карточках отображаются принятые участники, их возраст, демонстрационные аватары и рейтинги. Организатор может оставить общий режим 16+ или задать необязательные границы возраста «от» и «до». Backend не принимает заявку пользователя, который не соответствует заданному ограничению. Во вкладке «Мои» показываются напоминания о подтверждённых и собственных сходках на ближайшие семь дней.
 
Создать сходку на прошедшие дату и время нельзя: это проверяют frontend и backend. Прошедшие и отменённые сходки скрываются из активного каталога, но отменённые записи сохраняются в данных — позже на их основе можно сделать архив.
 
Время из формы преобразуется в ISO с часовым поясом устройства, поэтому backend корректно сравнивает его со своим временем. Открытый каталог автоматически обновляется раз в минуту.
 
До полноценного запуска приложения внутри MAX интерфейс использует демонстрационные профили.
 
## Технологии
 
- React, TypeScript, Vite
- Node.js, Express, TypeScript
- JSON-хранилище для воспроизводимой демонстрации MVP
- Docker и Docker Compose

## Архитектура и компоненты

```text
Пользователь в MAX или браузере
        ↓
React-приложение (apps/web)
        ↓ REST/JSON
Express API (apps/server)
        ↓
JSON-хранилище (data/db.json)
```

- **Frontend** показывает каталог, фильтры, карточки, формы, заявки и раздел «Мои сходки».
- **Backend** валидирует данные, управляет сходками и заявками, проверяет возрастные ограничения и скрывает точный адрес до подтверждения заявки.
- **Данные** хранятся в JSON-файле. При первом запуске рабочий файл создаётся из `data/seed.json`.
- **MAX API** используется для проверки подключения бота, команд `/start` и `/help` и будущих персональных уведомлений. Ошибка MAX не блокирует основные операции приложения.
- **Docker Compose** запускает frontend и API одной командой; данные API сохраняются в именованном томе `shodka_data`.

## Документация API

## Требования

- Node.js 20 или новее и npm — для запуска без контейнеров.
- Docker с поддержкой Docker Compose — для воспроизводимого контейнерного запуска.
- Токен MAX нужен только для работы чат-бота; каталог и основные сценарии можно проверить без него.

## Локальный запуск

macOS/Linux:

```bash
cp .env.example .env
npm install
npm run dev
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
npm install
npm run dev
```
 
Frontend: http://localhost:5173  
API: http://localhost:3000  
Проверка API: http://localhost:3000/health
Проверка подключения MAX: http://localhost:3000/api/max/status
 
Для локальной разработки бот получает события через long polling. Команды:
 
- `/start` — приветствие и кнопка для открытия сайта;
- `/help` — краткая справка.
 
Кнопка появляется, когда `MINI_APP_URL` содержит публичный HTTPS-адрес. Сейчас
это обычная ссылка на сайт. После регистрации URL мини-приложения в настройках
бота MAX кнопку можно заменить на кнопку Mini App. При
`http://localhost:5173` бот отвечает текстом, а интерфейс открывается отдельно
в браузере. Для production рекомендуется установить
`MAX_BOT_POLLING_ENABLED=false` и подключить webhook.
 
## Запуск через Docker

macOS/Linux:

```bash
cp .env.example .env
docker compose up --build
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
docker compose up --build
```
 
Frontend: http://localhost:8080  
API: http://localhost:3000

Остановка контейнеров:

```bash
docker compose down
```

Повторный запуск:

```bash
docker compose up --build
```

Обычная остановка не удаляет данные из тома `shodka_data`.
 
## Переменные окружения
 
| Переменная | Назначение |
|---|---|
| `PORT` | Порт backend |
| `WEB_ORIGIN` | Разрешённый origin frontend |
| `DATA_FILE` | Путь к файлу данных; локально `data/db.json`, внутри Docker `/app/data/db.json` |
| `MAX_BOT_TOKEN` | Токен бота MAX; хранится только в `.env` или секретах хостинга |
| `MAX_BOT_API_URL` | Базовый адрес API MAX: `https://platform-api2.max.ru` |
| `MAX_BOT_POLLING_ENABLED` | `true` для локального получения команд ботом; в production использовать webhook |
| `MINI_APP_URL` | Публичный HTTPS-адрес сайта; после регистрации в MAX — адрес Mini App |
 
## Демонстрационные пользователи
 
- `user-1` — Ира, 18 лет, обычный участник
- `user-2` — Саша, 25 лет, организатор тестовых активностей
- `user-3` — Лена, 16 лет, тестовый участник
 
В интерфейсе есть переключатель демонстрационного профиля. Он нужен только для показа полного сценария на одном устройстве: Ира подаёт заявку, затем Саша принимает или отклоняет её во вкладке «Заявки». После подключения MAX идентификатор должен поступать из проверенных данных платформы, а не из произвольного параметра клиента.
 
## Известные ограничения
 
- Используются подготовленные тестовые данные; реальная интеграция с каталогами событий отсутствует.
- Профили и аватары пока демонстрационные; идентификация через MAX Bridge ещё не подключена.
- Значения рейтинга являются тестовыми данными MVP; форма реального отзыва после завершения сходки пока не реализована.
- Напоминания работают внутри интерфейса. Для персональных сообщений от бота потребуется связать профиль приложения с MAX ID пользователя.
- Локально бот использует long polling; для production требуется публичный HTTPS webhook.
- Данные хранятся в JSON-файле и рассчитаны на один экземпляр сервера MVP.
- На бесплатном хостинге файл с пользовательскими данными может сбрасываться при перезапуске или новом развёртывании.
- Точный адрес скрыт в каталоге и возвращается участнику только после подтверждения заявки.
- Отдельный экран архива прошедших и отменённых сходок пока не реализован.
- Backend проверяет возраст демонстрационного профиля относительно лимита сходки, но подтверждение реального возраста и полноценная модерация не реализованы.
 
## Порядок проверки
 
1. Открыть frontend.
2. Выбрать карточку активности и нажать «Подать заявку».
3. Перейти в «Мои сходки» и убедиться, что заявка отображается со статусом ожидания.
4. Создать новую активность через форму.
5. Убедиться, что форма не позволяет выбрать прошедшие дату и время.
6. Переключить демо-профиль на Сашу, открыть вкладку «Заявки» и принять или отклонить заявку.
7. Открыть созданную Сашей сходку, нажать «Отменить сходку» и убедиться, что она исчезла из активного каталога.
8. Создать сходку с возрастным диапазоном и проверить, что возрастной лимит и возраст принятых участников отображаются в карточке.
 
## Безопасность
 
- Секреты не хранятся в репозитории.
- Точный адрес не показывается неподтверждённым участникам.
- В production необходимо валидировать данные запуска мини-приложения MAX на backend.
- Перед пилотом требуется проверить правила платформы и применимые требования к аудитории 16+, а также подготовить пользовательское соглашение с правилами безопасности и ответственностью сторон.
